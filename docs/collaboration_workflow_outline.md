# 教學投影片大綱 — 三層 AI 協作工作流
### Human × Claude Code × OpenEvolve：當 AI 也在指揮另一個 AI

> **目標受眾**：對 AI 協作 / agentic workflow 有興趣的學生
> **建議時長**：60–75 分鐘
> **總張數**：約 26 張，分 6 個 Part
> **素材來源**：本 session 真實發生的協作過程（OpenEvolve × CrewAI 專案）
> **慣例**：每張標 `🎤 講者備註`、`📊 視覺建議`、`💬 互動點`
> **敘事視角**：全程以**我（Human／本場講者）**的第一人稱講述；`Claude` 與 `OpenEvolve` 一律第三人稱；`你` 指台下學生

---

## 學習目標

（以下是我希望帶給台下學生的收穫）

1. 認識一個**三層嵌套的 AI 協作架構**：我指揮 AI、AI 駕馭另一個 AI
2. 理解每一層的**自主程度 vs 護欄**該如何配置
3. 從我的真實例子學會 5 個**可遷移的人機協作模式**
4. 帶走一條判準：**什麼我自己做、什麼交給 AI、什麼交給進化**

# Part 1 — 協作架構（5 張）

### Slide 4 — 三個角色登場
- 📊 三欄卡片：
  - **我（Human，本場講者）** — 設方向、做決策、提問、把關
  - **Claude Code（AI agent）** — 我的實作夥伴：實作、驗證、分析、誠實報告
  - **OpenEvolve 的 LLM（AI agent）** — Claude 駕馭的探索者：自主突變、發明工具、探索進化
- 🎤 關鍵：後兩者都是 AI，但角色完全不同；我站在最外層指揮

### Slide 5 — 三層嵌套架構（核心圖）
- 📊 同心圓 / 階梯圖：
  ```
  Human ──指揮──> Claude Code ──駕馭──> OpenEvolve LLM
  （意圖/決策）    （實作/判斷）        （自主探索）
  ```
- 每往內一層，**自主程度↑、但護欄也要越強**
- 🎤 這不是「我用工具」，是「我把自主性一層層往下委派」的三層鏈

### Slide 5b — Claude × OpenEvolve：架構師 vs 探勘者（關係圖）
- 📊 **核心關係圖**（已產出 SVG，直接放這張）：左藍「Claude＝架構師」、右琥珀「OpenEvolve＝探勘者」，中間是「設計搜尋空間 → 大規模探索 → 分析調整」的循環
- 對照表：

  | | Claude Code | OpenEvolve 的 LLM |
  |---|---|---|
  | 行為本質 | 有意圖的設計 | 無意圖的突變 + 篩選 |
  | 知不知道「為什麼」 | 知道（讀碼、推理、寫測試） | 不知道（由 fitness 決定誰活） |
  | 看得見框架嗎 | 看得見，而且框架是它搭的 | 看不見，在框架「內」探索 |
  | 量級 | 少量 · 高槓桿 · 可解釋 | 大量 · 低槓桿 · 靠數量 |
  | 產出 | 「是什麼 + 為什麼」 | 「是什麼」 |

- 🎤 金句：**不是誰比較強，是不同物種、各補一塊**——Claude 會精準設計但不會盲搜，OpenEvolve 會盲搜但不懂自己找到了什麼
- 🎤 我要學生看懂這個**循環**：Claude 設計搜尋空間 → OpenEvolve 探索 → Claude 分析再調整。iter22 就是這循環的產物

### Slide 6 — 每層的「自主 vs 護欄」
- 📊 表格：
  | 層 | 自主做什麼 | 護欄是什麼 |
  |----|-----------|-----------|
  | 我（Human） | 最終決策 | 自己的判斷、領域知識 |
  | Claude | 實作+分析 | 我的 review、git PR flow、誠實回報 |
  | OpenEvolve LLM | 突變+發明 | Failure Taxonomy（clamp/sandbox） |
- 🎤 金句：**我越是放手讓它自主，越要先建好「最壞只是退化、不是崩潰」的護欄**

### Slide 7 — 協作循環
- 📊 環形圖：我的意圖 → Claude 實作 → 驗證 → 誠實報告 → 我決策 → （下一輪意圖）
- 🎤 我和 Claude 的每個 PR、每個實驗都走這個循環

### Slide 8 — 為什麼這個架構值得學
- AI agent 越來越會「使用其他 AI/工具」→ 協作不再是單層
- 我想用這個專案示範：**如何安全地把自主性一層層往下委派**

# Part 2 — 各角色的職責（配真實例子）（4 張）

### Slide 9 — 我的角色：方向盤與煞車
- 我設方向（「優化 agent crew 各面向」）
- 我做不可逆決策（要不要 merge、跑哪個實驗、改不改系統）
- 我提問挑戰（驅動設計深化）
- 我把關流程（堅持 git PR flow）
- 🎤 真實例子：我堅持「main 只接受 PR」，有次 Claude 忘了開分支，被我當場糾正、立刻改回

### Slide 10 — Claude Code 的角色：實作與判斷
- 把意圖轉成程式碼 + 測試
- 讀原始碼**驗證**（不盡信文件）
- 跑實驗、分析數據
- **誠實報告**（主動揭露 bug 與限制）
- 維護文件 / PR
- 🎤 真實例子：讀 OpenEvolve 原始碼發現「EVOLVE-BLOCK 的『恰好一個』是建議非硬限制」

### Slide 11 — OpenEvolve LLM 的角色：自主探索者
- 在 Claude 搭的安全框架內**自主突變** agent prompt
- 發明新工具、探索進化路徑
- 🎤 真實例子：它自己進化出「按 user_std 切 4 段的評分預測公式」——沒人教它，連我和 Claude 都沒寫過

### Slide 12 — 三者互補，缺一不可
- 📊 維恩圖 / 三角圖：
  - 只有我（Human）：沒時間/精力做完所有實作
  - 只有 Claude：缺方向與最終判斷、會做出不可逆錯誤
  - 只有 OpenEvolve：會把自己改崩潰（v3 的 36% 失敗）
- 🎤 三層各補一塊，缺了我這一層就沒方向

# Part 3 — 五個協作模式（真實例子）（6 張）

### Slide 13 — Pattern 1：提問深化設計（招牌案例：Tool Use → 失敗分類學）
- **我問的好問題（原話放投影片）**：我問的不是「幫我修 bug」，而是——
  > 「怎麼讓 agent 安全地進化、用不同工具、甚至創造新工具，而不會在 tool calling 上崩潰？」
- **我的問題逼出來的好答案**：Claude 沒有直接寫 try/except，而是先做**失敗分類學（Failure Taxonomy）**，把「tool calling 失敗」拆成 5 層：
  - L1 協定 / L2 參數 / L3 策略 / L4 消化 / L5 合約
  - → 導出安全憲法「**graceful degradation, not catastrophic crash**」
  - → 落地成 L0 觀測 + L1 clamp executor + L2 sandbox（4 道閘門）
- **成果**：工具崩潰率 v3 的 **36% → 0 次**
- 📊 視覺建議：左「我的一句開放問題」→ 右「5 層分類學 + 0 崩潰」的對比
- 🎤 金句：**好問題的價值高於好答案**——是我「往深處問」，把一個隨手的修補逼成可遷移的分層框架
- （小例補充）同類：我問一句「為什麼不是 data_retriever？」→ Claude 把決策點 vs 資料點的設計 reasoning 寫進設計文件，成為永久知識

### Slide 14 — Pattern 2：誠實回報，主動抓 bug
- combined_score=0.8452 看似完美
- Claude 主動**直接驗證 `agent.tools`** → 發現是 `[]`（工具根本沒裝上）
- 揭露 + 補回歸測試
- 🎤 金句：**分數健康 ≠ 功能正確**；AI 的誠實性是協作的地基

### Slide 15 — Pattern 3：我把關不可逆操作
- merge PR、跑 4 小時實驗、`brew install`、改系統設定
- Claude **先問我再做**，不擅自執行不可逆動作
- 🎤 真實例子：建新 GitHub repo、裝 LibreOffice 前，Claude 都先問我確認

### Slide 16 — Pattern 4：人機知識互補
- Claude 不知道「我的 Mac 闔蓋會中斷背景進程」
- 我提醒 → Claude 解釋 caffeinate 機制 + 幫我設定（防系統睡眠但讓螢幕休息）
- 🎤 我的「環境/物理世界知識」補 Claude 的盲點；Claude 的「工具細節」補我的

### Slide 17 — Pattern 5：分層委派自主（最核心）
- 我請 Claude 為 OpenEvolve 的 LLM **搭安全框架**（L0/L1/L2 Failure Taxonomy）
- 框架到位，我才敢「放手讓它自主進化」
- 📊 對比：v3（沒框架）36% 崩潰 vs 完整架構 0 次工具崩潰
- 🎤 **我委派自主性的前提，是先建好「最壞只是退化」的護欄**

### Slide 18 — 五模式總表
- 📊 一頁回顧 5 個 pattern + 各自的真實例子
- 💬 互動點：問「哪一個模式你明天就能用在自己的專案？」

# Part 4 — 高潮案例：iter22 的誕生，與它「之後」的深挖（4 張）

### Slide 19 — 三層協作跑出一個進化產物
- 📊 三層貢獻流程圖：
  - **我（Human）**：決定「用完整架構跑 50 iter」+ 設定 caffeinate 讓它整夜跑完
  - **Claude**：搭好 L0/L1/L2 框架、啟動進化、脫離 harness、分析數據
  - **OpenEvolve LLM**：自主進化出 iter22 的「量化分段公式」（0.842）
- 📊 可放 iter22 公式片段：按 `user_std` 切 4 段做評分預測，clamp [1,5]、round 0.5

### Slide 20 — 沒有任何一層能單獨做到
- 我不會手寫那套公式、Claude 不會自己想到那個公式、OpenEvolve 沒框架會崩潰
- 🎤 iter22 是**我們三層協作的湧現產物**

### Slide 21 — 真正深刻的地方：iter22「之後」發生了什麼（核心新增）
- 我請 Claude 追了 iter22 (de559de9) 的**所有衍生子代**，結論：**iter22 之後，再沒有更好的後代**
- 📊 演化方向圖（停滯）：
  - 後代走向 **over-engineering**：4 段公式 → 5、6 段，加更多參數
  - `preference_estimation` 微幅波動，但 `review_generation` **反而退化** → combined_score 停滯
  - migration 把 iter22 基因散到 3 島 → **三島趨同**，多樣性塌掉，整族卡同一山頭
- **Claude 給我的診斷**：iter22 是**局部最優**；要跳出去不是再多跑 iter（會繼續 over-engineer），而是 **加大 TASKS 讓 fitness 訊號更紮實 + 島嶼種子多樣化** 打破趨同
- 🎤 金句：OpenEvolve 能「找到」iter22，但「**為什麼停在這、怎麼跳出去**」是探勘者**結構上做不到**的——它沒有「局部最優」這個概念。這一塊得靠 Claude（有意圖的分析者）補上，而方向由我來定
- 💬 互動點：問台下「如果只看分數曲線，你會發現它卡住了嗎？」

### Slide 22 — 連「失敗」也是協作的洞察
- 8 次低分崩潰 → 我請 Claude 爬梳資料歸因（5 次 YAML 壞掉 + 3 次 rate limit 429）
- 🎤 協作不只產出成功，也**共同理解失敗**——成功與失敗都是我們三層一起讀懂的

# Part 5 — 反思與 Takeaways（2 張）

### Slide 23 — 什麼該誰做？
- 📊 三欄判準：
  - **我（Human）親自做**：方向、價值判斷、不可逆決策、領域/物理知識
  - **交給 Claude**：實作、驗證、分析、文件、誠實回報
  - **交給進化（OpenEvolve）**：在安全框架內的大規模探索與發明
- 🎤 我用三條判準分工：可逆性、是否需要價值判斷、搜尋空間大小

### Slide 24 — Key Takeaways
1. AI 協作正在變成**多層**——學會「委派自主性」是新技能
2. 每往下一層，**護欄要越強**（最壞只是退化，不是崩潰）
3. **誠實回報 + 人類把關不可逆** = 協作的安全地基
4. 好問題驅動好設計；連失敗都能共同理解
- 💬 互動點：回收開場提問「你的 AI 是工具還是夥伴？」
